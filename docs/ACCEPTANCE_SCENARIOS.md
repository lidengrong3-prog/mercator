# 第八板块：验收场景

本文件对应“必须覆盖的验收场景”。`tests/fixtures/acceptance_scenarios.json` 是隔离的自动化测试夹具，明确标记为 `production_ingest: false`，不会被页面、数据校验或 Supabase 同步流程加载。

| 场景 | 本地自动化覆盖 | 生产验收前置条件 |
| --- | --- | --- |
| 美国 + 宠物用品/美妆/3C/家居 + Amazon/TikTok Shop | 已覆盖目录、范围、品类章节和平台章节 | 接入对应美国真实商品、政策、规则和准入数据 |
| 印尼 + 服装/美妆/3C/家居 + TikTok Shop/Shopee/Lazada | 已覆盖目录、范围和平台关系；印尼目录当前为 `schema_only` | 接入印尼真实市场、平台、政策、税收和准入数据 |
| 同一平台在不同市场使用不同规则 | 已覆盖 TikTok Shop US/ID 规则隔离 | 两个市场均有官方或可追溯规则记录 |
| 同一品类在不同市场使用不同税收和准入条件 | 已覆盖 beauty 的 US/ID 税收和准入隔离 | 两个市场均有已核验税收和准入记录 |
| 多市场、多品类同时生成报告 | 已覆盖市场比较、市场章节和品类章节 | 各必需数据域达到发布门槛 |
| 只有政策数据、没有商品数据 | 已覆盖无商品事实、提示词禁止生成排名 | 报告生成请求必须经过数据检查 |
| 没有成本和售价 | 已覆盖财务模型返回 `incomplete` | 前端不得绕过财务检查写入确定性利润 |
| 全球政策未匹配当前市场 | 已覆盖 Global 记录被当前范围过滤 | 正式数据必须带明确市场适用范围 |
| 关键数字可回溯来源和数据快照 | 已覆盖来源附录、来源记录 ID、快照时间和范围快照 | 保存报告时需成功写入云端快照与版本字段 |

## 执行

```powershell
npm test
$env:JAY_PLAYWRIGHT_BASE_URL='http://127.0.0.1:4174'
npm run test:browser
```

如果没有可复用的本地服务，浏览器测试默认使用 `4173` 启动静态服务器。生产验收还必须执行 `scripts/production_acceptance.py`，并确认数据质量报告为可发布状态；`schema_only` 市场不能被描述为已接入事实数据。
